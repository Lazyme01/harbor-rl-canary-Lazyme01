# Section 6: Dense verifier and trajectory analysis

## Dense reward

`tests/test_state.py` runs three independent checks and prints the weighted
score; `tests/test.sh` writes that score to `/logs/verifier/reward.txt`.

| Check | Weight | Coverage |
|---|---:|---|
| CLI and status accounting | 0.20 | Random private transaction IDs, amounts, statuses, and timezone-aware timestamps; checks the CLI and exact JSON totals/counts. |
| UTC deduplication and equal-time tie-break | 0.50 | Random amounts and offsets create a lexical-order trap for a newer UTC instant and an equal instant whose later CSV row must win. |
| Invalid input validation | 0.30 | A valid positive control plus malformed header, missing timezone, negative amount, invalid status, and malformed row; invalid inputs must fail with stderr output. |

Expected outputs are calculated from each generated input using `Decimal`.
Identifiers, values, timestamps, and temporary input paths vary at verifier
runtime. Fixture data is generated by the verifier under `tests/`; none is
stored in `environment/`. The score is the sum of weights for checks that pass.

The hardcoded-output example in `solution/hack.sh` replaces the candidate
program with a constant response for one fixed sample. It does not read or
modify verifier files. In an isolated container it scored `0.00` against the
randomized verifier.

## Saved job replay

Each final candidate was reconstructed from its recorded terminal write
command in `agent/trajectory.json`, then run in an isolated Python 3.12
container against both the preserved binary test source and the new dense
verifier. The binary replay score agrees with the saved verifier reward for
all six trials.

Baseline means: binary `0.667`, dense `0.767`. Ablation means: binary `1.000`,
dense `1.000`. The one baseline failure earned only the invalid-input weight;
it failed the CLI/status and UTC-deduplication checks.

## Artifact availability and limitations

The per-trial artifact manifests contain only the generic `/logs/artifacts`
mount and do not provide final source snapshots. However, each of the six
trajectories contains the terminal command that wrote its final implementation
(the `2tHFABd` trial wrote `reconcile_fixed.py` and then moved it into place).
Those recorded commands were sufficient to reconstruct and replay all six
candidates. Reconstructed files and score data were created under `/tmp` and
removed after replay; the saved job directories were not modified.

The dense categories are intentionally all-or-nothing at their assigned
weights, so scores are limited to the sums of `0.20`, `0.50`, and `0.30`.
No model API trials were run.
